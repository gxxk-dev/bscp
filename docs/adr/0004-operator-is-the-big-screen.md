# 操作端就是投屏的那块大屏

操作与呈现发生在同一块屏上：操作者站在大屏前直接操作画布，没有第二台控制设备，
因此也不存在设备间同步。投屏呈现的是画布的当前视口。

理由：这是形态最简的一种——省掉实时同步（WebSocket / CRDT）、省掉设备配对与鉴权、
省掉「以哪块屏为准」的状态冲突。而守在大屏前操作本来就符合现场的实际姿态：
操作者课前在大屏前把资料摆好，多一个设备就多一道隔阂。

（注意本产品**不承担授课过程中的操作**——摆好、投出去、用完就关，
授课本身用希沃白板。见 `CONTEXT.md` 的场景范围。）

## Considered Options

- **笔记本或平板操作，大屏只显示**：屏幕更大更清晰、操作者不必走到大屏前，
  但需要双端实时同步，架构重一个量级，课前还多了一台要连的设备。

## Consequences

- 屏幕既是操作面又是呈现面，**操作痕迹会被学生看到**——课前摆好的过程
  学生就在旁边看着。悬浮控件、选中框、缩放手柄
  在设计上必须克制，不能出现大工具栏。「UI 偏小」不只是密度偏好，更是场景要求。
- 画布交互要同时适配触控与鼠标，控件得能被手指在大屏上准确点中。
- 视口状态是纯本地状态，不涉及跨端一致性问题。
