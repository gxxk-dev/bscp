# 重跑解析作用于一份资源，不作用于整块画布

重跑解析重算并覆盖**这一份资源**产生的全部区域，以及它们在画布上的编排。
画布上**其他资源的编排不受影响**。仍然不合并——不合并这条缩到资源级，不变。

这条修正 [ADR-0005](./0005-parse-on-demand-overwrite-everything.md) 的「重跑覆盖画布上的
**全部**编排」。`CONTEXT.md` 对画布的定义本来就写着「重跑解析时按资源归属精确清理」——
之前它与 ADR-0005 矛盾，现在以资源归属为准。

## 为什么

**因为画布支持多份资源共存，而「整块覆盖」等于让每一份资料为另一份资料陪葬。**
画布上摆了两份资料，重跑第 2 份，第 1 份已经摆好的编排跟着没了。而两份资料之间
本来毫无关系——它们只是恰好在同一个屏上。

**因为在重跑不可撤销之后，这条从「不方便」变成了「必错」。**
[ADR-0011](./0011-no-rollback-rasterize-once.md) 取消了回滚。同样是「覆盖别的资源」，
能退回去时它只是别扭，不能退回去时它就是一次无法挽回的误伤。

**因为确认框报的数字必须只算这一份。** 报整块画布的数，会让操作者为了重跑一份资料、
误以为自己要赔上全部已摆好的编排。那种确认框不是在保护，是在劝退。

## Consequences

- **确认框的措辞与计数都改成「这一份资源」**，不是「整份编排」。报出来的块数只数
  这一份资源里被操作者亲手挪过的块。
- **重跑入口最终要挂在某一份资源上**（每份资源一个入口），而不是画布级的全局按钮。
  原型里画布通常只有一份资源，入口位置不变，但它的语义已经是「重跑这一份」。
- **区域必须带资源归属，而且归属是行为依据，不只是角标上的文字**：它决定谁有权
  覆盖这一块。原型里 `artifact` 同时承担「显示用的文件名」和「归属」两个角色，
  真实实现需要独立的资源 id——同名文件投两次应当算两份。
- **不合并仍然成立，作用域缩到资源级**：这一份资源的新旧解析结果不合并。
- **单份资源时行为不变**：原型目前就是单份，所以这条改的是语义与文案，不是画面。
