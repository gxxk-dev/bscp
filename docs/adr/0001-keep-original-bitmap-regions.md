# 版面以原始位图区域为主，只对需要改字号的文字做矢量化

资源的区域默认从原图上裁切，保留原始位图（路线甲）；只有当文字区域需要改字号、
需要检索、或需要换行重排时，才对它做矢量化（路线丙，以甲为主）。

理由是失败模式的严重程度不对称。白板场景里，操作者读错一个字的代价远大于字迹略糊，
而矢量化路线的失败模式恰好是「认错字」，裁切位图路线的失败模式只是「不够漂亮」。
OCR 与版面模型因此退化为**理解**工具——用来判断哪里是一个语义单元、阅读顺序是什么——
而不是**重建**工具。

## Considered Options

- **纯矢量化重排**：OCR 出全部文字，用排版引擎重排干净页面。可搜索、可任意缩放，
  但识别质量决定一切，公式、图表、手写批注是硬骨头，且失败时输出不了可用的结果。
- **纯裁切**：完全不动文字。实现最简，但「字太小」这一条故障永远解决不了。

## Consequences

- 需要两套渲染路径：位图区域与矢量化文字区域，版面要能混排两者。
- 文字区域的字体、行高、断行由我们决定，因此要处理中英文混排与公式回退。
- 原图必须长期保留（不能算完就丢），版面数据只存区域的框与引用。
