# 决策模型与 LLM 都是必需组件，都走可替换接口，选型不锁死

**两个 AI 组件都是首版的必需品，不是「以后再上」：**

| 组件 | 做什么 | 接口（固定） | 首版 |
|---|---|---|---|
| **决策模型** | 版面检测 + 区域切分 | 输入页位图 → 输出区域框列表（可带块间邻接关系） | 接一个能跑通的实现 |
| **LLM** | 语义单元分组 | 输入区域框 + 页码 + 来源 → 输出哪些区域属于同一语义单元 | 接一个 |

**接口固定，选型开放。** 「各种都可以弄」意味着首版不锁死具体模型：实现必须放在
接口后面，换后端只改配置与实现，不改调用方。两者都**支持多后端可切换**（AGENTS.md
的既有要求），API key 与 baseURL 绝不下发客户端。

**两者都只提议。** 拆分与分组都可被操作者推翻（[ADR-0010](./0010-ai-proposes-only-arrangement-is-manual.md)），
摆放永远不交给 AI。

## 为什么

**因为没有它们就没有这个产品。** 决策模型解决的是「哪里是一块内容」——那是整条管线的
起点；LLM 解决的是「哪几块是一道题」——那是整组拖动的前提。这两件事都是产品的核心
能力，不是锦上添花。推迟它们等于推迟产品本身。

**因为把接口定死比把选型定死更重要。** 校内场景的输入差异很大（扫描件、拍照、
电子版 PDF），而模型在中文试卷上的表现差异会很大。把接口定死，首版接一个能跑的，
后面按真实效果换——比在开工前赌一个模型合适要划算。

## Consequences

- **失败路径必须分开说。** 决策模型失败 = 解析失败，编排保持原样（spec 第 39 条）。
  LLM 分组失败或超时 = **不分组**，解析仍然成功——因为拆分已经成功了，
  让分组挂掉整次解析是把一个次要步骤当成必要步骤。操作者可以手工分组。
- **测试用录制的固定输出，不在测试里跑真模型。** 判据是「版面检测返回的区域框」
  这个稳定接口，不是某个模型的输出格式。
- **分组要等所有区域出来**，因此它天然在拆分之后。课前准备的延迟预算要按
  「拆分 + 分组」两段合计来定，而不是只算拆分。
- **具体选型仍未定**：`docs/research/decision-models.md` 有候选与调研，
  但首发接哪个要等第一份真试卷上的实测。
