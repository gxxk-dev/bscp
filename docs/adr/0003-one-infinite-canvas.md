# 只有一块无限画布，不分页

画布是唯一的工作区，也是唯一的投屏对象。不存在「页」这个概念——
没有固定尺寸的页面对象，也没有翻页动作。

理由：这套产品要解决的核心故障里就包含「一页过满」和「字号太小」，
而分页恰恰是把内容塞进固定的一屏；用分页去解决分页造成的病，方向是反的。
正确的方向是**把内容摊到更大的空间里**——一页的内容拆开后由操作者摊在画布上，
每一块都能被放大到可读。跨文件也一样：把两份资料的片段摆在一起看，
在无限画布上是自然的，在固定页模型里则要先把它们硬拼成一页。

## Considered Options

- **幻灯片模型**（每页一块固定视口的画布）：交互习惯最熟悉，但「自由」被页框住，
  跨页搬运、跨文件拼接都很别扭，且会重新引入「一页装不下」的原始病。
- **分页画布 + 页框**（画布上画出页边界）：折中，但仍然是分页思路的变体。

## Consequences

- 投屏呈现的是画布上的一个视口，而不是一个页面对象——需要画布坐标系与缩放模型。
- 没有「下一页」这个动作，**也不需要替代它的导航手段**：本工具的使用形态是
  「上课前临时把资料摆好 → 投出去 → 用完就关」，摆好那一刻就是终点，
  不存在「现场找不到内容」的时间窗口。真正的授课发生在希沃白板里，不在这里。
  （本条修正了早期「必须补导航手段」的推论——那是从「无限画布丢了分页」这个
  结构事实推出来的，没有回到场景验证损失是否真的发生。）
- AI 的产出不再是「排好一页」，而是「把资源拆成区域」（见
  [ADR-0010](./0010-ai-proposes-only-arrangement-is-manual.md)：AI 只拆分，摆放是人工的）。
