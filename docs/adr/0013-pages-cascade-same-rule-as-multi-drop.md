# 多页资源横向错开成叠，与多份投放共用同一条摊开规则

一份 PDF 有多页时，解析完成后**每页是完整的一页位图，各页横向向右下错开成叠**，
像把一叠纸在桌面上摊开：从第 1 页起，每一页比上一页右下各错开一个等步长。
每页露出一角和角标上的页码，**不纵向拉长画布**。

**多份资源投放用同一条规则。** 一次投三份资料，和一份资料有三页，摊开方式是同一个：
从第一份/第一页开始，每一份/页向右下错开一个等步长，收拢时按**整叠**算。

## 为什么

**因为纵向堆叠会把画布拉长，操作者得平移才能看到后面的页。** 一份十几页的资料
纵排是几千像素高，1440×900 的屏一次只看得到一两页——那等于把「这份资料一共多少页」
这个最该一眼看到的信息藏了起来。

**因为错开成叠让「整份资料」保持一个整体的形状。** 一叠纸在桌上是一个东西；
十几张纸竖成一列是十四个东西。前者能一眼数清，后者不能。

**因为只有一条规则就不需要两套代码。** 「多份投放」和「多页摊开」在模型上是同一件事：
一个有序的摊开序列，每一项有自己的矩形和来源标注。写成两套，日后必然出现
「为什么三份是这么摆的而三页不是」这种没法回答的问题。

## Consequences

- **摊开规则必须是纯函数**：输入一组带尺寸的项 + 一个起点 + 一个步长，
  输出每一项的位置。它不关心项是资源还是页。
- **步长由第一项的尺寸算出并封顶**（当前：短边 14%，夹在 28–72px）。
  太小看不出是两份，太大后面几项就甩出屏外。
- **收拢按整叠算，不按单项算。** 单项收拢会把错开压回并排，恰好毁掉这一屏要证明的事。
- **多页资源的区域带页码角标**，多份资源的区域带文件名角标。两者都是「这一块
  来自哪里」，但答案不同：前者答「第几页」，后者答「哪份文件」。
- **原型里「页」已经存在**（区域带 `page` 字段），所以这不是新模型，是把已有的
  `page` 真正用起来——摊开、角标、重跑时按页清理。
- **重跑的作用域是资源**（[ADR-0012](./0012-reparse-one-artifact.md)），所以重跑
  这一份资源会重新摊开它的**全部**页，而不是只重跑当前可见的那一页。
