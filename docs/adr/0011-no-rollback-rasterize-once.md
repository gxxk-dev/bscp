# 重跑不可撤销，栅格化产物只服务这一次

重跑解析覆盖画布上的全部编排，**不留快照、不能撤销**。栅格化只服务这一次的解析与
编排，**不为换分辨率保留原始资源**。

这条修正了两个既有 ADR 的一部分：

| 被修正 | 出处 | 仍成立的部分 |
|---|---|---|
| 「覆盖前在浏览器内存里留一份快照，供本次会话内回滚」 | [ADR-0005](./0005-parse-on-demand-overwrite-everything.md) | 解析按需触发、重跑覆盖全部编排、不做合并 |
| 「原始资源必须保留：重新栅格化是换 DPI 的唯一手段」 | [ADR-0008](./0008-image-only-rasterize-first.md) | 一切资源先栅格化、区域永远是位图 |
| 「栅格化可缓存」「栅格化放服务端是因为它必须和缓存与原始资源在一起」 | [ADR-0009](./0009-rasterize-server-side-pdf-images-only.md) | 栅格化在服务端用 PyMuPDF、首版只收图片与 PDF |

## 为什么

**因为撤销缓冲买到的保护，是一整套「要记住上一次状态」的机制。** 快照要有存放，
要有引用有效性（区域增删改之后旧引用指哪），要跨资源归属（一次重跑覆盖整块画布时，
快照里的编排还指着哪几份资源）。而这个场景是**课前摆一次、讲完就关**——那份状态
在它存在的时间里，从来不会被用到第二次。用一个课堂不会发生的场景，换一整套机制。

**因为真正的防线是说出来，不是退得回去。** 覆盖前如果承诺「可以回滚一次」，
操作者反而会为了保险先点一次试试——于是这个承诺本身把不可撤销变成了常态。
不如一开始就说清这一步不能撤销，让他把力气花在拍板和摆位置上。

**因为「一次性」把整条管线的性质说清楚了。** 一份资源从投进来到投出去只走一遍：
栅格化 → 解析 → 拍板 → 编排 → 投屏。走完就散。取消保留之后，服务端不需要资源实体的
生命周期管理——不需要按哈希查缓存，不需要知道某份资料还在不在，不需要清理过期原件。
**「这份资料还在不在」从此永远是个不用回答的问题。**

## Considered Options

- **会话内快照（ADR-0005 原方案）**：只在「手滑」这个时间尺度上有用，代价是整套
  状态快照机制，而课堂现场几乎不会用到它。
- **快照存服务端、可跨会话回滚**：保护更强，但要引入服务端版本存储——为一个
  用完就关的工具建一套历史。
- **保留原件以便换 DPI 重新栅格化（ADR-0008/0009 原方案）**：把最高精度锁在第一次
  导入那一刻确实是个损失，但它买的是一个**首版没有的场景**（换分辨率重投），
  代价是原件得一直留着。

## Consequences

- **确认框不再出现「可以回滚一次」**，改为明说这一步不能撤销。仍然必须强确认、
  仍然必须报出实际会丢几块——[ADR-0005](./0005-parse-on-demand-overwrite-everything.md)
  的「误操作没有第二道防线，UI 侧用强确认补偿」因此比原先更吃重，而不是更轻。
- **工具条上的「撤销」入口删除。** 它从来没有真正实现过，只弹一个演示提示；
  留着一个假的撤销，比没有撤销更糟。
- **路径表里所有以「可撤销」作退路的条目必须换成真存在的那条退路**：拍板前可改框、
  分组可拆可合、切碎可合回。删掉一个退路不等于没有退路，是退路得说真的。
- **不再有跨请求的栅格化缓存**，同一份 PDF 投两次就渲染两次。单页渲染是毫秒级的，
  而一个能跨请求的缓存需要一个「这份资源还在不在」的管理面——那正是被取消的东西。
- **[ADR-0009](./0009-rasterize-server-side-pdf-images-only.md) 的结论不变，理由换了**：
  不再因为「栅格化必须和缓存、原件待在一起」，而是因为决策模型本来就在服务端
  （[ADR-0006](./0006-self-hosted-vision-layer.md)），而几百 DPI 的一页 A4 有几 MB——
  **重活不落在课堂那台一体机上**。
- **重跑的对象仍然是整块画布，还是只清某一份资源，需要重新定。** 画布支持多份资源
  共存（见 `CONTEXT.md`），而一次性让「每份资源各走一遍自己的管线」变得自然。
  本 ADR 不决定这件事：它只取消回滚，不取消重跑。
