# 板上重排 · 首版 spec

> 状态：草案。原型（`prototype/`）已把交互问题答完，12 条行为路径可执行可断言。
> 本 spec 把原型学到的交互约束与 `docs/adr/` 的决定合成为一份可实现的规格。
> 硬决定的依据一律引 ADR，不在这里重述。

## 原型的地位

**原型不扔，它是本 spec 交互部分的 primary source。** 下面那 12 条交互不变量不是
我在文档里推出来的，是原型里跑出来的——每一条都有对应的断言和截图。实现时
**以原型为准，本 spec 描述意图**；两者不一致时，先怀疑本 spec 抄错了。

它同时是行为路径表的可执行版本：12 条路径 × 32 屏，每一屏都能用 URL 直接定位，
断言的是行为不是实现。

```
cd prototype
bun install
bun run dev          # 打开后用 ?path=<key>&step=<从 0 起> 定位到任意一屏
bun run build        # tsc --noEmit + vite build
bun run smoke        # Playwright 驱动真实 preview 服务器，32 屏全断言
```

`step` 超出该路径范围会自动夹到最后一屏；`path` 不认识会退回第 1 条。
键盘 ←/→ 切路径、↑/↓ 切屏、Esc 退投屏。

**原型的已知边界**（别拿它当产品承诺）：场景数据是 mock 的，只有投放这一条是真能用的
（真文件过 MIME 闸门、真图片显示、锚在光标、摊开与收拢）；解析、语义单元、AI 调用
全是假数据；投屏是同屏切换而不是真的投出去；没在希沃一体机上验过。

## Problem Statement

校内白板要现场投屏资料，而资料自身的排版不适合直接展示：字太小、排得太满、
一屏塞不下、切口穿过内容。操作者想做的事只有一件——**把资料拆成看得清的几块，
按他要的样子摆，再投出去**。

现在这件事靠人在希沃白板上硬凑：截图、裁剪、拖位置、调大小。每一份资料要花
十几分钟，而且「凑出来的版面」记不住，下次讲同一份还得再凑一遍。

而现有工具的方向是反的：它们要么保留原文件的排版原样投上去（于是看不清），
要么提供强大的文档编辑能力（于是要学）。中间那一档——**只解决重排，不解决别的**——
没有工具。

## Solution

把资源整页栅格化成位图，让决策模型在位图上提议「哪里是一块内容」和「哪几块
属于同一道题」，操作者拍板之后，把区域摊到画布上按他要的方式摆，投出去。

**这个产品只做重排。** 不留存、不检索、不导航、不承担授课过程中的操作——讲课时
用希沃白板，这个工具在课前把东西摆好就退出。

## User Stories

### 投放

1. 作为操作者，我要把图片或 PDF 拖到画面上任意位置，以便不用先对准某个小框
2. 作为操作者，我要一次投多份资料，以便把卷子、板书照片、实验报告一起摆
3. 作为操作者，我要投进来的资料**出现在我松手的位置**，以便东西和手指对得上
4. 作为操作者，我要在靠近屏幕边缘投放时内容自动收拢进视野，以便我不用再把它拖回来
5. 作为操作者，我要在投了 Word 文档时立刻知道「不收」以及为什么，以便我知道怎么办
6. 作为操作者，我要在一次投放里混着可收与不可收时，被逐个点名收了哪些、拒了哪些，
   以便我不至于以为拒掉的文件也在
7. 作为操作者，我要有第二条投放路径（点一下选文件），以便触控设备上不方便拖拽时也能用
8. 作为操作者，我要在投放回执里看到文件名与体积，以便确认投对了

### 解析与拍板

9. 作为操作者，我要显式触发解析，以便画布不会在我没准备好时被改写
10. 作为操作者，我要看到解析产出的每一块区域，以便判断切得对不对
11. 作为操作者，我要未被拍板的区域**一眼可见**（虚线），以便不会漏审
12. 作为操作者，我要在选中某块时就地浮出「接受 / 改框」，以便不用跑到屏幕另一头
13. 作为操作者，我要能拖四角手柄改裁切框，以便切口穿过字时当场纠正
14. 作为操作者，我要能「全部接受」以便快速过一遍
15. 作为操作者，我要能看到 AI 提议的语义单元（哪几块是一道题），以便整组拖动
16. 作为操作者，我要能拆开或合并提议的分组，以便推翻 AI 的判断
17. 作为操作者，我要在切割太粗时能继续切碎，以便后排看清
18. 作为操作者，我要在切碎之后能把一块投出去占满整块屏，以便那一块的内容足够大
19. 作为操作者，我要表格按行切分，以便切出来的东西读得下去

### 碎开与编排

20. 作为操作者，我要解析完成后整份资料轻微裂开，以便我看出「哪一块原本挨着哪一块」
21. 作为操作者，我要**摆放完全由我做**，以便版面是我要表达的东西而不是算出来的东西
22. 作为操作者，我要拖一块就是拖一块，以便摆位跟手
23. 作为操作者，我要拖组里任意一块时同组的一起走，以便一道题整体移动
24. 作为操作者，我要没有任何吸附、对齐线、AI 建议位置，以便画面里出现的每一分都出自我
25. 作为操作者，我要双指缩放与空白处平移，以便看细节
26. 作为操作者，我要**相机不跟我的手抢方向**——投放、拖块、增删区域都不动相机，
    以便画面不会在手底下滑动
27. 作为操作者，我要拿起哪一块哪一块就前移并保持，以便层次和我的手一致
28. 作为操作者，我要多份资料与多页都能一眼看清有几份/几页，以便发现漏页
29. 作为操作者，我要每块能认出自己来自哪份资料的哪一页，以便投出去时不投错

### 投屏

30. 作为操作者，我要一键把当前编排投出去，以便开始上课
31. 作为操作者，我要投屏态画面上**没有任何操作痕迹**（提示条、控件、角标、选中框），
    以便观众看到的就是资料本身
32. 作为操作者，我要在投屏与操作态之间来回切换而位置一模一样，以便反复确认不重摆
33. 作为操作者，我要用系统级动作（希沃遥控的退出键）退出投屏，以便画面上不摆退出口
34. 作为操作者，我要能只把一块投出去占满屏，以便那一块足够清楚

### 重跑

35. 作为操作者，我要能重跑解析，以便裁切或分组不满意时重来
36. 作为操作者，我要在重跑前被强确认，并被告知**这一份**里会丢几块，以便我知道自己在赌什么
37. 作为操作者，我要在重跑时保持画布上其他资料的编排，以便别的资料不受牵连
38. 作为操作者，我要知道重跑不可撤销，以便不做无脑确认

### 失败与出路

39. 作为操作者，我要在解析失败时保持画布原样，以便不丢已摆好的东西
40. 作为操作者，我要在服务端不可用时看到可理解的错误，而不是白屏
41. 作为操作者，我要在投了 DOCX 时拿到「另存为 PDF 或截图再投」这条出路，以便有下一步

## Implementation Decisions

### 技术形态

- **前端**：Vite 7 + React 19 + TypeScript 5.9（`strict` + `noUncheckedIndexedAccess`）+
  Tailwind CSS v4 + `@heroicons/react/20/solid`。状态不用外部库——单个画布用
  React state 足够，引 Zustand/Redux 只是多一层间接。
- **后端**：单运行时 **FastAPI**。ADR-0009 已把服务端的 Python 依赖定成
  PyMuPDF + PaddleOCR 系（决策模型在服务端自托管，ADR-0006），再引一个 Node
  运行时等于凭空多一套部署和两条 API。
- **形态**：PWA + SPA。后端必须存在（栅格化与视觉层都在服务端，ADR-0009）。
- **服务端是会话式的**（ADR-0014）：一次课前准备 = 一个会话，会话持有页位图。
  这意味着 API 是**有状态**的——会话 id 要一路带着，「会话没了」要是一个明确错误
  而不是 404。解析中的会话不因 TTL 被回收。
- **API key 绝不下发客户端**，LLM 与决策模型都要支持多后端可切换（AGENTS.md）。
  这里的「多后端」指**多个 LLM 后端**可切换（首发 OpenRouter 的 Space Bunny，
  ADR-0016）；视觉层本身也要可替换，但走自托管、配置切换。

### 区域模型（原型产出，决策密集）

```ts
type Region = {
  id: string; x: number; y: number; w: number; h: number;
  page: number;            // 来自这一份的第几页
  artifact?: string;       // 来自哪一份资源。**归属是行为依据**：决定谁有权覆盖它
  unit: string | null;     // 语义单元 id，null = 不属于任何一组
  /* 内容载荷：裁切位图，或继续切碎派生出来的子块 */
};

type Board = {
  regions: Region[];
  touched: string[];       // 操作者亲手拖过的块。碎开不写这里
  pending: string[];       // 未拍板（虚线）
  selected: string | null;
  editing: string | null;
  groups: boolean;         // 语义单元可见
  badges: boolean;         // 来源角标可见
};
```

**`positions` 与 `touched` 必须分开。** 解析完成会碎开——各块从版面中心向外轻轻挪一点。
那是一次呈现，不是编排。操作者随后拖动块才是编排，而重跑解析抹掉的只有后者。
确认框里「你挪动了 N 块」数的是 `touched`，不是位置——否则碎开会让它永远显示 6 块，
或者永远显示 0 块。两个数都不是人话，警告框就废了。

**渲染顺序就是 `regions` 的顺序，也就是层次。** 不另设 z-index 通道。

### 交互不变量（原型逐一验过，代码注释不再是唯一记录）

1. **相机只归操作者。** 自动取景只在两种触发下发生：换屏、按「适应画布」。
   投放、拖块、增删区域一律不动相机。早期把 `board.regions` 放进取景的依赖里，
   于是拖一块就重新居中，每一帧画面都在手底下滑动——那不是手感问题，
   是相机在跟操作者抢方向。
2. **投放锚在松手光标**，靠近边缘时**按整叠**收拢进当前视野，收拢只动新内容。
3. **一次可投多份**，摊开用 ADR-0013 那条规则（向右下等步长错开），步长由第一项
   短边算出并封顶在 28–72px。收拢按整叠算——单项收拢会把错开压回并排。
4. **默认大小按当前视野的份额等比收**（宽 42% / 高 60%），**小的不放大**。
   放大插值出来的字是糊的，而这份资料等下要投到大屏上看。
5. **混着收与拒必须一次逐个点名**。静默丢掉拒收的那些，操作者会以为都在。
6. **碎开**：从版面中心向外径向散开，位移 ≈ 块短边的 8%，加**确定性**扰动
   （同一个 id 每次结果相同——随机会让评审者以为碎开每次不同）。只写位置，
   不进 `touched`。
7. **层次：拿起即前移并保持。** 整组一起前移、组内相对顺序不变。层次写进
   `regions` 的顺序，不写在 CSS 里——早先只有拖动期间的一句 `z-10`，松手就撤，
   块按下去浮起来、一松又沉回去。
8. **一次操作只写一次状态。** 选中写进同一次 board 更新，不走第二条通道——
   两条通道写同一份状态，后写的会用事件前的快照盖掉先写的。
9. **投屏态零操作痕迹**：提示条、底部控件、角标、分组标、选中框全部撤掉；
   进出一致，退出靠系统级动作。
10. **重跑不可撤销**（ADR-0011），且**作用域是这一份资源**（ADR-0012）：
    确认框报这一份里被挪过的实际块数、明说别的资源不动、明说不能撤销。
    **承诺过能退比什么都不说更糟**——操作者会为了保险先点一次试试。
11. **工具条**：单层 flex + `gap-x-3`、按钮统一 36px、48px 触控命中区在 12px
    间距下首尾相接不重叠、一道分隔线隔开编排控件与动作、每屏最多一个 primary、
    危险动作用 muted + 红色图标。规范来源是 design skill（= ui.sh 规范集）。
12. **区域永远带资源归属**，归属决定谁能覆盖它——不只是角标上的文字。

### 管线

投放 → 闸门（只收图片与 PDF，拒收当场说清并给出路）→ 服务端整页栅格化成位图 →
决策模型提议区域切分 → LLM 提议语义单元分组 → 碎开 → 操作者拍板与编排 → 投屏。

**AI 只提议拆分与分组，从不摆放**（ADR-0010）。区域在画布上的位置完全由操作者决定。

**提高可读性靠切分粒度，不靠提高分辨率**（ADR-0008）。栅格化分辨率是整条管线的
精度天花板，但瓶颈从来不是 DPI，是那块内容占得太小。

## Testing Decisions

**好测试只验外部行为。** 不验内部状态，不验类名，验的是「屏幕上发生了什么」。

- **主接缝**：Playwright 驱动一个**真实的 preview 服务器**，对着构建产物跑。
  断言行为不实现——这是唯一能同时验到 DOM、相机 transform、控件顺序的接缝。
- **12 条行为路径 × 每一屏**：每一屏都不许有运行时错误；每屏最多一个 primary；
  热点层不许盖住正需要操作的按钮；投屏态痕迹必须为零；进出一致。
- **行为断言举例**（每一条都对应上面某条不变量）：
  - 碎开位移 ≥ 12px 且朝版面中心向外
  - 拖动全程相机 transform 恒定
  - 拿起的块前移后保持，点空白处不许压回去
  - 投放内容锚在光标 ±4px 内，丢在右下角自动收拢
  - 3000×2000 的实拍照按视野份额收进屏内，100×100 的小图不放大
  - 工具条间距 ≥12px、高度一致、相邻中心距 ≥48px、分隔线恰好一道
  - 重跑确认框报实际块数、不出现「回滚」、必须出现「不能撤销」
- **闸门要真文件过一遍 MIME 判定**，否则测不到「这个格式收不收」——真实的
  File 对象才有真实的 `type`。
- **决策模型与 LLM 必须在接口后面可替换**：测试用录制的固定输出，
  不在测试里跑真模型。判据是「版面检测返回的区域框」这个稳定接口，不是某个模型的输出格式。
- **栅格化用真实 PDF 与图片**测，不用 mock——「服务端渲染的页是不是真的能显示出来」
  只有真渲染能验。

## Out of Scope

- **留存、检索、导航**：不是知识库。用完就关。
- **授课过程中的操作**：讲课时用希沃白板，这个工具不参与。
- **DOCX**：首版只收图片与 PDF（ADR-0009）。拒收必须给「另存为 PDF 或截图再投」的出路。
- **单份资料超过 10 页**：首版在闸门处拒收并给出「拆成几份分别投」的出路
  （ADR-0017）。超出不静默截断。
- **任何形式的文字重建**：区域永远是裁切位图（ADR-0008）。
- **提高分辨率**：伪需求（ADR-0008）。
- **撤销与回滚**：重跑不可撤销（ADR-0011）。
- **AI 摆放**：ADR-0010。也没有吸附、对齐线、推荐位置。
- **按内容定位**：区域里的字读不到，「打一个词跳到那块」做不到。这是有意的取舍。
- **多用户、账号、云同步**。
- **自动排版 / 模板 / 版式库**。

| 希沃真机验收 | **不阻塞，降优先级** | — |

### 仍然没定的

1. **视觉层具体接哪个**。ADR-0016 定了「必需、接口固定、选型开放」，
   但首发接哪个要等第一份真试卷上的实测（`docs/research/decision-models.md` 有候选）。
2. **LLM 的第二、第三个后端**。首发只有 Space Bunny 一个；多后端可切换是硬约束，
   但备选是谁没定。
3. **一次解析的延迟预算**。课前准备能等多久，决定了决策模型能不能用大的、
   要不要并行、以及要不要给分组设超时。
4. **多页摊开的真实观感**。ADR-0013 的算术在 ≤10 页内成立，但 10 页摊成 10 层错开
   之后还认不认得出「这是同一份的 10 页」，需要拿真试卷看一眼。
5. **Space Bunny 的隐私面**。`stealth` 是匿名第三方供应商，prompt 可能被留存——
